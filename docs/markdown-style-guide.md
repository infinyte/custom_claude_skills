# Markdown Style Guide

## Scope

This style guide applies to repository-level docs and skill support docs.

## Structure

- Use exactly one H1 per file.
- Use title case headings.
- Keep section depth shallow when possible.

## Lists

- Use numbered lists for ordered steps.
- Use bullet lists for unordered content.
- Keep list items short and specific.

## Links and Paths

- Use relative links for repository files.
- Prefer explicit paths over ambiguous text.
- Validate links after file moves or renames.

## Naming

- Use kebab-case for most markdown filenames.
- Reserve uppercase names only where convention strongly requires it.

## Writing Conventions

- Prefer active voice and concrete language.
- State purpose, scope, and expected outputs early.
- Avoid duplicate authority by designating one canonical doc per topic.

## Required Sections For Canonical Docs

- Purpose
- Scope
- How To Use
- Maintenance Notes

## Versioning And Change Notes

- Keep changelog details in canonical files, not in duplicated summaries.
- Mark superseded files clearly and point to the canonical replacement.
